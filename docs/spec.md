# 異世界冒険ゲーム 全体仕様書 v0.1

> この文書は、Codexに実装を依頼するための仕様書です。
> リポジトリの `docs/spec.md` に置き、「17. 実装フェーズ」の順に依頼してください。
> 数値に（仮）と付いているものは、プロトタイプを動かしながら調整する前提の初期値です。

## 1. ゲーム概要

- 様々な世界を冒険し、人間（職業持ち）やモンスターを仲間にして育てる、スマホブラウザ向けRPG
- 戦闘は「方舟のホムンクルス」型：行動ゲージ制・フルオート・スキル優先度とクールタイムで制御
- プレイヤーの遊びの中心は「負けた理由を戦闘結果から読み取り、編成・スキル・装備を組み替えて再挑戦する」こと
- 趣味での個人運営。課金要素は当面なし（将来追加できる設計にしておく）

## 2. 技術構成

| 役割 | 採用技術 |
|---|---|
| フロントエンド | TypeScript + Vite（静的ビルド）、スマホ縦画面前提のSPA |
| 配信 | Cloudflare Pages |
| API | Cloudflare Workers（ルーティングは Hono） |
| データベース | Cloudflare D1 |
| 画像 | リポジトリ内で管理しPagesから配信。容量が増えたらCloudflare R2へ移行 |
| 定期処理 | Workers Cron Triggers（日次・週次リセット、PvPシーズン集計） |
| ソース管理 | GitHub（スマホのブラウザから画像・マスターデータを編集できるようにする） |

### 2.1 リポジトリ構成（案）

```
/docs/spec.md            この仕様書
/packages/engine/        戦闘エンジン（純粋なTypeScript。DOMにもWorkersにも依存しない）
/packages/master/        マスターデータ（JSON）と型定義・読み込み処理
/apps/api/               Workers + Hono（D1を使用）
/apps/web/               フロントエンド（Vite）
/apps/web/public/img/chara/   キャラ画像
/apps/api/migrations/    D1のマイグレーションSQL
```

### 2.2 実装上の大原則

1. **サーバー権威**：戦闘・ガチャ・報酬・育成の計算はすべてWorkers側で行う。クライアントは表示とリクエストのみ
2. **決定的な戦闘**：戦闘エンジンは `Math.random()` や `Date` を使わず、シード付き疑似乱数（例：mulberry32）だけを使う。同じ入力（編成データ＋シード＋ルール）なら必ず同じ結果になること
3. **データ駆動**：キャラ・スキル・装備・世界・ルール・イベント・ガチャはすべてマスターデータ（JSON）で定義し、追加時にコード修正が不要な構造にする
4. **人間とモンスターは同一仕様**：データ上も処理上も区別しない（表示用の分類タグを持つだけ）
5. **軽い計算**：1戦あたりのCPU時間を小さく保つ（Workersは1リクエストのCPU時間に上限がある。無料プランは特に短いので、本運用では有料プランを想定）
6. **エンジンの単体テスト**：戦闘エンジンは Vitest でテストを書き、仕様の各ルールを検証する

## 3. 戦闘システム

### 3.1 基本ルール

- 1パーティ4体。敵味方合わせて最大8体
- 人間とモンスターは同一のユニット仕様。敵もプレイヤーのキャラと同じ仕様で、ステージデータでランク・レベル・スキル構成を指定する
- 戦闘中の操作はなし（フルオート）
- 決着：どちらかの4体全員が戦闘不能になったら終了
- **最大200ターン**。200ターン経過で決着していなければ**プレイヤー側の負け**（PvPでは挑戦側の負け）

### 3.2 行動順（行動ゲージ）

- 行動ゲージの最大値：1000
- 全員が0からスタートする（例外：「戦闘開始時ゲージ+X」のようなスキル・パッシブ効果）
- 処理ループ：
  1. 生存している全ユニットのゲージに、それぞれの素早さを加算する
  2. ゲージが1000以上のユニットがいれば、その中で1体を選んで行動させる
  3. 行動したユニットのゲージから1000を引く（超過分は持ち越す）
  4. 1000以上のユニットが残っていれば、1の加算をせずに2へ戻る。いなければ1へ
- 同時に1000以上のユニットが複数いる場合の優先順：
  1. ゲージ値が高い
  2. 素早さが高い
  3. プレイヤー側（PvPでは挑戦側）
  4. 編成の並び順が上
- **1ターン = 1体の行動**。誰かが1回行動（行動不能で番を飛ばした場合も含む）するごとに、全体のターン数が1増える
- 素早さの値の幅は、最遅と最速でおおむね2倍以内に収まるようにデータを設計する（詳細は 4.3）

### 3.3 ステータス

**基本ステータス（ランクとレベルで伸びる）**

| 項目 | 役割 |
|---|---|
| HP | 0で戦闘不能 |
| 攻撃 | 物理スキルの威力 |
| 防御 | 物理ダメージの軽減 |
| 魔力 | 魔法スキルの威力・回復量 |
| 魔防 | 魔法ダメージの軽減 |
| 素早さ | 行動ゲージの増加量 |

**特殊ステータス（％。キャラ固有の固定値＋装備・スキルで上乗せ。レベルでは伸びない）**

| 項目 | 役割 |
|---|---|
| 会心率 | 会心の発生確率 |
| 回避率 | 攻撃を完全に回避する確率 |
| 命中率 | 相手の回避率を打ち消す |
| ヘイト | 敵から狙われやすさの重み（目安：盾役3・標準2・後衛1） |

### 3.4 スキルと行動選択

- アクティブスキル：**6枠**（固有スキル1〜3個 ＋ 汎用スキル枠。合計が常に6）
- パッシブスキル：キャラごとに2〜5個の候補があり、その中から**2つ**を装備する
- 各アクティブスキルは、プレイヤーが設定する**優先度（0〜3）**と、スキル固有の**クールタイム（CT）**を持つ
- MPは存在しない。スキルの制約はCTのみ
- 行動時の選択：
  1. CTが0（使用可能）のスキルを候補にする
  2. 候補のうち優先度が最も高いものを使う
  3. 同じ優先度なら、スキル枠の並び順が上のものを使う
  4. 候補がなければ通常攻撃（物理、倍率1.0、敵単体、CTなし）（仮）
- 使用したスキルのCTは、スキルの設定値にセットされる

### 3.5 攻撃の処理順

1. **命中判定**：実際の回避率 = 対象の回避率 − 攻撃側の命中率。0%〜50%の範囲に収める。「必中」タグを持つスキルはこの判定を飛ばす
2. **会心判定**：会心率で判定し、成功ならダメージ1.5倍
3. **ダメージ計算（比率式）**
   - 物理：攻撃 × スキル倍率 × 攻撃 ÷（攻撃 ＋ 防御）
   - 魔法：魔力 × スキル倍率 × 魔力 ÷（魔力 ＋ 魔防）
   - 回復：魔力 × スキル倍率（防御の概念なし）
4. **乱数**：最終値に 0.95〜1.05 を掛け、端数を切り捨てる（最低1ダメージ）
5. バフ・デバフ・世界ルールによる補正は、計算に使うステータスの段階で掛ける

### 3.6 ターゲット選択

スキルごとに対象の種類を持つ。

| 対象種別 | 内容 |
|---|---|
| enemy_single | 敵単体（ヘイト抽選） |
| enemy_all | 敵全体 |
| enemy_random_n | 敵ランダムにn回（各回ヘイト抽選） |
| enemy_lowest_hp | HP割合が最も低い敵（ヘイト無視） |
| ally_single | 味方単体（仮：HP割合が最も低い味方） |
| ally_all | 味方全体 |
| ally_lowest_hp | HP割合が最も低い味方 |
| ally_dead | 戦闘不能の味方（蘇生用） |
| self | 自分 |

- **ヘイト抽選**：生存している相手のヘイト値の合計を母数にした重み付き抽選
- 挑発スキルでヘイトを一時的に上げ、隠密スキルで下げられる
- 条件付き（lowest_hp系）の対象はヘイトを無視する

### 3.7 持続の数え方（CT・状態異常・バフ）

- すべて**そのユニット自身の行動回数**で数える
- **行動終了時に1減らす**
- 行動不能（スタン・睡眠・麻痺による失敗）で番を飛ばした場合も「1回行動した」とみなしてカウントを進める

### 3.8 状態異常

| 名前 | 効果 |
|---|---|
| 毒 | 行動終了時に最大HPの5%のダメージ |
| 火傷 | 行動終了時に最大HPの3%のダメージ ＋ 攻撃ダウン |
| スタン | 次の1回の行動が不可 |
| 睡眠 | 行動不可。ダメージを受けると解除 |
| 麻痺 | 行動のたびに50%の確率で行動不可 |
| 沈黙 | 魔法カテゴリのスキルが使えない（物理スキルと通常攻撃のみ） |
| 混乱 | 敵単体スキルの対象が、敵味方の生存ユニットからランダムになる（仮：自分は除く） |

- **付与判定**：スキルの付与率だけで判定する（耐性ステータスはなし）。耐性はパッシブ（例：毒無効、状態異常耐性+20%）で表現する
- **重ねがけ**：同じ状態異常を再び受けたら、残り持続の長いほうで上書き（効果は重ならない）

### 3.9 バフ・デバフ

- 対象：攻撃・防御・魔力・魔防・素早さ・会心率・回避率・命中率
- 同じ項目のバフ・デバフは加算する。合計は±50%で打ち止め
- 持続は3.7のルールに従う

### 3.10 戦闘不能と蘇生

- HPが0になった時点で戦闘不能
  - 行動ゲージが止まり、行動しない
  - 状態異常・バフ・デバフはすべて解除
  - ヘイト抽選と全体スキルの対象から外れる
- 蘇生：
  - HP30%で復帰（スキルごとに調整可）。行動ゲージは0から再スタート
  - **同じユニットの蘇生は1戦闘につき1回まで**（連戦ダンジョンでは連戦全体で1回）
  - 蘇生スキルは長めのCTを設定する

### 3.11 世界ルール

- 戦闘の場（ステージ・連戦ダンジョン・イベント・PvP）ごとに、ルールのリストを持つ
- 通常：世界のルールを1つ適用。高難度・ボス戦：追加ルールを1つ重ねて合計2つ
- **敵味方の両方に適用**する
- ルールは既存の仕組み（ステータス補正・状態異常・継続ダメージ・スキル種別の補正）の組み合わせで表現し、エンジンに個別処理を増やさない
- 例：
  - 灼熱：全員が行動終了時に最大HPの2%のダメージ
  - 魔素：魔法スキル威力+30%、物理スキル威力−20%
  - 霧：全員の命中率−20%
  - 時の歪み：全員の素早さ+50%
  - 静寂：全員、自分の行動10回まで沈黙状態

### 3.12 戦闘結果の出力（スナップショット）

- エンジンは戦闘の途中経過をすべて返すのではなく、**50・100・150・200ターン時点**（途中で決着した場合は決着時点まで）のスナップショットと最終結果を返す
- スナップショットの内容（ユニットごと）：
  - キャラID、陣営、HP／最大HP、戦闘不能か
  - 状態異常・バフ・デバフの一覧（種類・残り持続・効果量）
  - 行動回数、与ダメージ累計、被ダメージ累計（仮：振り返り用）
- 最終結果：勝敗、決着ターン、決着理由（全滅／時間切れ）、蘇生の使用状況
- 画面：スナップショットをページ送りで表示（キャラ画像＋HPバー）。キャラをタップすると、その時点の状態異常などの詳細をポップアップで表示

### 3.13 エンジンの入出力（インターフェース案）

```ts
interface BattleInput {
  seed: number;
  attackers: UnitSetup[];   // 4体まで（プレイヤー側 / PvPの挑戦側）
  defenders: UnitSetup[];   // 4体まで（敵側 / PvPの防衛側）
  rules: RuleId[];          // 適用する世界ルール
  carryOver?: CarryOver;    // 連戦ダンジョンの引き継ぎ（HP・戦闘不能・蘇生使用済み）
  maxTurns: number;         // 通常200
  snapshotInterval: number; // 通常50
}

interface BattleOutput {
  result: 'win' | 'lose';   // attackers視点
  reason: 'wipe' | 'timeout';
  endTurn: number;
  snapshots: Snapshot[];
  carryOut: CarryOver;      // 次の戦闘への引き継ぎ情報
}
```

`UnitSetup` は、ランク・レベル・覚醒・装備・スキル構成から**サーバー側で計算済みのステータス**と、スキル・パッシブの設定を持つ。エンジン自体は育成の仕組みを知らなくてよい。

## 4. キャラ育成

### 4.1 設計方針

- **どのキャラも育てきれば最高ランク（SS）に到達でき、同じランク・同じレベルなら総合力は互角**
- 同ランク同士の差は、ステータスの配分（尖り方）、固有スキル、パッシブ候補、覚醒段階、装備、汎用スキルの組み方でつく
- インフレを避けるため、各育成要素の役割を分ける

| 要素 | 役割 |
|---|---|
| レベル | 基本ステータスの成長、スキルポイントの増加 |
| ランク・昇格 | レベル上限の再解放、ステータスの底上げ |
| 装備 | 特殊ステータスと型の変更 |
| 覚醒 | パッシブ候補の開放、固有スキルの強化（ステータスは微増のみ） |

### 4.2 ランクとレベル

- ランク：**F → E → D → C → B → A → S → SS**（8段階）
- レベル：各ランクで **Lv1〜30**（全ランク共通）（仮）
- 昇格条件：Lv30到達 ＋ 昇格素材 ＋ ゴールド。昇格するとLv1に戻る
- 必要経験値はランクが上がるほど増える
- 昇格直後（次ランクLv1）が、昇格前（前ランクLv30）よりわずかに強くなるように総量を設計する

### 4.3 ステータスの計算（配分比率方式）

- 各キャラは、HP・攻撃・防御・魔力・魔防の**配分比率**（合計100%）を固有値として持つ
- ステータス総量はランクとレベルだけで決まり、全キャラ共通：
  - `総量(rank, lv) = BASE[rank] × (1 + (lv − 1) × g)`（仮：g = 0.03）
  - `BASE[rank+1] = BASE[rank] × (1 + 29g) × 1.05`（昇格直後に約5%上回る）
- 各ステータス = 総量 × 配分比率 × 項目係数（仮：HPのみ係数を大きくする。例 ×5）
- **素早さは配分比率に含めない**。`素早さ = 基準素早さ(rank, lv) × 素早さ係数` とし、素早さ係数はキャラ固有で 0.7〜1.4（仮）の範囲。これで最遅と最速の差を約2倍に収める
- 特殊ステータス（会心率・回避率・命中率・ヘイト）はキャラ固有の固定値
- 覚醒1段階ごとにステータス総量+1.5%（仮）
- 最終ステータス = 上記 ×（1 + 装備の割合補正）

### 4.4 スキルポイントと汎用スキル

- スキルポイントの総量は **ランクとレベルだけで決まる**（入手経路に関係なく同じ値）
  - 例：ガチャでSランクLv1のキャラを入手 → FからSのLv1まで育てたキャラと同じポイントを最初から持つ
- 汎用スキルは全キャラ共通のリストから選ぶ
- 汎用スキルには**コスト**（仮：1〜8）があり、汎用枠にセットしたスキルのコスト合計がスキルポイント以下になるように組む
- 付け替え（振り直し）は**いつでも無料**
- 固有スキルはコストなし・外せない

### 4.5 覚醒

- 段階：**0〜4**
- 覚醒の手段：同じキャラを重ねる、または**覚醒石**（全キャラ共通）を使う
- 効果：
  - 覚醒0：パッシブ候補のうち最初の2つが使える
  - 覚醒1〜3：閉じているパッシブ候補を1つずつ開放。すべて開放済みなら固有スキルを強化（威力アップ／CT短縮など、スキルデータで定義）
  - 覚醒4：固有スキルの最終強化、または見た目の変化（覚醒立ち絵・枠・称号）
  - 各段階でステータス総量+1.5%（仮）
- 覚醒段階は昇格しても引き継ぐ

### 4.6 経験値

- 入手：戦闘報酬、経験値アイテム（戦闘報酬やダンジョンで入手。好きなキャラに使える）
- 出撃メンバー（4体）：100%
- **控え枠**（初期4体、拠点で最大8体）：30%（拠点で最大50%）
- 控え枠に入っていないキャラには入らない（サーバーの書き込み量を抑えるため）

### 4.7 キャラの入手

| 経路 | 対象 |
|---|---|
| ガチャ | 初期ランクB〜SSのキャラ |
| 戦闘報酬 | ステージ・ダンジョンの報酬として |
| 戦闘後に仲間になる | 初期ランクF〜Cのキャラ。各世界ごとに決まった顔ぶれが一定確率で仲間になる |

- 仲間産もガチャ産も、育てれば同じようにSSまで到達できる

### 4.8 分解

- 覚醒しきったキャラの重複や、余った仲間キャラは**分解**できる
- 分解で得られるもの：覚醒石のかけら（仮：10個で覚醒石1個）とゴールド。初期ランクが高いほど多い
- 交換ポイント（ガチャの天井）は分解では得られない

## 5. 装備

- 枠：**武器・防具・装飾品**の3枠。人間もモンスターも装備できる（説明文は自由）
- **装備自体の強化はしない**。世界を冒険して集め、付け替える
- 効果の種類：
  - 基本ステータスの**割合**上昇（例：攻撃+10%）
  - 特殊ステータスの上昇（例：会心率+5%、回避率+8%、ヘイト+1）
  - 特殊効果（例：攻撃時に毒付与20%、確率で追撃、炎系スキル威力+20%）
- 後半の世界ほど「強い」装備ではなく「尖った」装備が出る（例：回避+15%／防御−10%）
- 装備は個体（インスタンス）で管理する。1つの装備は同時に1体にしか付けられない

## 6. 経済と戦闘回数

### 6.1 通貨・素材

| 名前 | 用途 |
|---|---|
| ゴールド | 昇格費用、拠点強化など |
| ジェム | ガチャ。現状は1種類のみ（将来の課金に備え、データに「種類」の項目を持たせる） |
| 昇格素材 | ランク帯ごとの共通素材：小（F→E、E→D）、中（D→C、C→B）、大（B→A、A→S）、極（S→SS） |
| 覚醒石／覚醒石のかけら | 覚醒 |
| 経験値アイテム | キャラへの経験値付与 |
| イベントアイテム | 期間イベントの交換所用 |

### 6.2 戦闘回数の制限

- **スタミナなし**
- **連続戦闘の間隔制限**：1戦ごとに3秒（仮）の待ち時間。判定はサーバー側で行う
- **まとめて周回**：
  - 1回のリクエストで同じステージ／ダンジョンを最大10回（初期5回、拠点の転移門で最大10回）
  - 待ち時間は回数に比例（10回なら30秒）
  - 途中で全滅または時間切れになったらその時点で終了
  - 結果は合計報酬をまとめて表示。スナップショットは**最後の1戦だけ**保存する

## 7. 冒険（世界とダンジョン）

### 7.1 世界の構成

1つの世界は次のデータをひとまとめにした単位。新しい世界はデータの追加だけで作れること。

- テーマ・名前・短い紹介文
- 世界ルール
- ステージとダンジョンの一覧
- 出現する敵の顔ぶれ
- その世界で仲間になるキャラ（初期ランクF〜C）
- その世界で手に入る装備
- ボス戦前の一言（短いテキスト）

### 7.2 世界の解放

- **序盤の3世界は一本道**（チュートリアルを兼ねる）
  - 1つ目：穏やかなルール。基本操作を覚える
  - 2つ目：世界ルールを本格的に体験
  - 3つ目：連戦ダンジョンを体験
- **後半は段階（層）ごとに解放**
  - 3世界で1つの段階。同じ段階の3世界をすべてクリアすると次の段階が開く
  - 段階の中ではどの順番で攻略してもよい
  - 世界のクリア条件：その世界の連戦ダンジョンのボスを倒す
  - 推奨ランクの目安：序盤F〜E → 第1段階D〜C → 第2段階B〜A → 最終段階S〜SS
- 運営で世界を追加するときは、既存の段階に足すか、新しい段階として最上位に積む

### 7.3 ステージと連戦ダンジョン

| 種類 | 内容 | 主な用途 |
|---|---|---|
| ステージ | 1戦で完結 | メイン進行、日常の周回 |
| 連戦ダンジョン | 3〜5戦 ＋ ボス | ボス戦、高難度、上位素材・良い装備 |

連戦ダンジョンの引き継ぎ：

- **引き継ぐ**：HP、戦闘不能状態、蘇生の使用回数
- **リセットする**：行動ゲージ、CT、状態異常、バフ・デバフ
- 各戦闘は200ターン上限。どこかで全滅または時間切れになれば失敗
- まとめて周回では、連戦ダンジョン1回分を1周として数える

### 7.4 ストーリー

- 世界ごとの短い紹介文と、ボス戦前の一言のみ

## 8. ガチャ

- 排出ランク：**B〜SS**（F〜Cは仲間専用）
- 排出率（仮）：B 65% ／ A 25% ／ S 8% ／ SS 2%
- 10連で **A以上1体確定**
- 価格（仮）：1回150ジェム、10連1500ジェム
- 天井（交換ポイント式）：
  - 1回引くごとに1ポイント
  - **200ポイント**でピックアップキャラ1体と交換
  - ピックアップ期間は**3週間**
  - 期間終了時に残ったポイントは覚醒石などに変換
- 排出率はゲーム内で必ず表示する
- 「特定の組み合わせをそろえると報酬」という形式（コンプガチャ）は作らない
- 課金は当面なし。ジェムはすべてゲーム内で配布する

### 8.1 ジェムの配布ペース（目標：1日10連分 = 1500ジェム）

| 入手元 | 量（仮） |
|---|---|
| デイリー任務（全達成） | 1日1000 |
| ウィークリー任務 | 週2100（1日約300） |
| 世界の初回クリア・イベント報酬など | 1日平均約200 |

## 9. デイリー・ウィークリー任務

- リセット時刻：毎日5:00（日本時間）（仮）。ウィークリーは月曜5:00（仮）
- デイリー任務（例）：
  - 戦闘に5回勝利する
  - キャラを1回昇格させる、または覚醒石を1個使う
  - 連戦ダンジョンを1回クリアする
  - 全達成でボーナス
  - 報酬：ジェム、ゴールド、経験値アイテム
- ウィークリー任務（例）：
  - ボスを3体倒す
  - 新しい装備を5個手に入れる
  - 報酬：ジェム多め、覚醒石
- 任務は「たくさん周回させる」より「いろいろな遊び方に触れる」内容にする
- 任務の内容はマスターデータで定義する

## 10. 期間イベント

- 期間：**3週間**。ガチャのピックアップ期間とそろえ、テーマに合ったキャラをピックアップする
- **イベントの世界**：通常の世界と同じデータ形式。ステージ（周回用）と連戦ダンジョン（イベントボス）、イベント専用の特殊ルール
- **イベント限定の仲間**：イベントの世界でだけ仲間になる低ランクキャラを1〜2体
- **イベントアイテム**がドロップする
- **交換所**：
  - 報酬：イベント限定装備、ジェム、覚醒石、昇格素材など
  - 報酬ごとに**交換上限**を設定する（周回し放題のため）
  - イベント終了時に残ったイベントアイテムはゴールドに変換
- イベントは「世界データ ＋ 期間 ＋ 交換所の表」のデータだけで作れること

## 11. 拠点

- 表示形式：**メニュー形式**（施設一覧から選んで強化）。将来1枚絵の拠点画面に差し替えられるよう、施設データと表示を分けておく
- 施設はゴールドと素材で強化。最大レベル5（仮）
- 効果はすべて「広げる」系。**キャラのステータスは上げない**

| 施設 | 効果 |
|---|---|
| 作戦室 | 編成プリセットの保存数（4体の編成・スキル構成・優先度・装備を丸ごと保存） |
| 訓練所 | 控え枠の数（4→8）、控えの経験値割合（30%→50%） |
| 倉庫 | キャラ・装備の所持上限 |
| 転移門 | まとめて周回の最大回数（5→10） |
| 資料館 | 図鑑。キャラ・装備の収集数に応じたコレクション報酬（ジェム・ゴールド） |

- 施設は冒険の進行に合わせて解放する（例：序盤で作戦室と倉庫、後半に入ったら転移門と資料館）

## 12. PvP（ランキング戦）

### 12.1 形式

- **非同期PvP**：各プレイヤーが「防衛編成」を登録し、他のプレイヤーがそれに挑戦する
- 防衛編成は**登録時点の状態をまるごと保存**する（計算済みステータス・スキル構成・装備）。登録後に育成しても、再登録するまで反映しない
- 戦闘はサーバーで計算するので、相手がオフラインでも成立する

### 12.2 ルール

- 時間切れ（200ターン）は**挑戦側の負け**
- 同時行動の優先は**挑戦側**
- **週替わりの世界ルール**を1つ適用（通常の世界ルールのデータを流用）
- 挑戦回数：1日10回まで（仮）

### 12.3 ポイントとシーズン

- シーズン：**1週間**（世界ルールの切り替わりと同時）
- シーズン開始時、全員**1000ポイント**
- 挑戦に勝利：基本+20。相手とのポイント差で増減（格上ほど多く、格下ほど少なく）
- 防衛で敗北：挑戦側の獲得分の半分程度を失う
- 挑戦で敗北：ポイントは減らない
- 順位はポイントの多い順

### 12.4 対戦相手

- 挑戦画面で、自分のポイント前後から3人（少し格上・同程度・少し格下）を提示
- 相手の選び直しは1日数回まで無料（仮：3回）
- プレイヤーが少ない時期のために、**運営が用意したNPCの防衛編成**をランキングに混ぜる

### 12.5 報酬とログ

- シーズン報酬は**順位の割合**で区切る（上位1%、10%、30%、参加者全員など）
- 報酬は**称号・アイコン枠など見た目中心**（強さに影響しない）
- 防衛側は、挑まれた対戦の結果をスナップショットで確認できる

| 種類 | 仕様 | ファイル名 |
|---|---|---|
| 立ち絵 | 2:3の縦長（例：1024×1536）、透過WebP | `chara_001_full.webp` |
| 覚醒4の立ち絵（任意） | 同上 | `chara_001_full_awake.webp` |
| 専用アイコン（任意） | 正方形（例：256×256）、WebP | `chara_001_icon.webp` |

- アイコン表示の優先順位：**専用アイコン → 立ち絵からの切り出し → 仮アイコン（名前の頭文字を丸で囲んだもの）**
- 覚醒4で覚醒立ち絵があれば表示を切り替える。なければ枠やエフェクトで代用
- 立ち絵を使う場面：キャラ詳細、図鑑、ガチャ演出、ホーム画面（お気に入りキャラ1体）
- アイコンを使う場面：戦闘スナップショット、編成、一覧、PvP
- 画像は自作、または利用許可のある素材のみを使う

## 14. データ設計

### 14.1 マスターデータ（`/packages/master/` のJSON）

型の案（TypeScript）。フィールドは実装時に増やしてよいが、この形を基本とする。

```ts
type Rank = 'F'|'E'|'D'|'C'|'B'|'A'|'S'|'SS';

interface CharacterMaster {
  id: string;                 // 'chara_001'
  name: string;
  kind: 'human' | 'monster';  // 表示用の分類のみ。処理では区別しない
  job?: string;               // 職業・種族の表示名
  initialRank: Rank;
  statRatio: { hp: number; atk: number; def: number; mag: number; mdef: number }; // 合計100
  speedFactor: number;        // 0.7〜1.4
  special: { crit: number; evade: number; accuracy: number; hate: number };
  uniqueSkills: string[];     // 1〜3個
  passiveCandidates: string[];// 2〜5個（並び順が開放順）
  awakenBonus: AwakenBonus[]; // 覚醒段階ごとの固有スキル強化内容
  image: { faceX: number; faceY: number; cropSize: number }; // 立ち絵からのアイコン切り出し（割合 0〜1）
  recruitable?: { worldId: string; rate: number }[];        // 仲間になる世界と確率
  description: string;
}

interface SkillMaster {
  id: string;
  name: string;
  kind: 'unique' | 'generic';
  category: 'physical' | 'magical' | 'heal' | 'support' | 'revive';
  power: number;              // 倍率
  target: TargetType;         // 3.6 の表
  hits?: number;              // enemy_random_n の回数
  cooldown: number;           // 行動回数
  sureHit?: boolean;
  effects?: SkillEffect[];    // 状態異常付与・バフ・デバフ・ヘイト変化・ゲージ操作など
  cost?: number;              // 汎用スキルのみ
  description: string;
}

interface PassiveMaster {
  id: string;
  name: string;
  trigger: 'always' | 'battle_start' | 'on_action_end' | 'on_hit' | 'on_ally_down'; // 必要に応じて追加
  effects: SkillEffect[];
  description: string;
}

interface EquipmentMaster {
  id: string;
  name: string;
  slot: 'weapon' | 'armor' | 'accessory';
  statPercent?: Partial<Record<'hp'|'atk'|'def'|'mag'|'mdef'|'spd', number>>;
  special?: Partial<Record<'crit'|'evade'|'accuracy'|'hate', number>>;
  effects?: SkillEffect[];
  worldId?: string;
  description: string;
}

interface RuleMaster { id: string; name: string; effects: SkillEffect[]; description: string; }

interface WorldMaster {
  id: string; name: string; intro: string;
  tier: number;               // 0 = 序盤の一本道、1以降 = 段階
  order: number;              // 序盤の一本道での順番
  ruleIds: string[];
  stageIds: string[]; dungeonIds: string[];
  bossDungeonId: string;      // クリア条件
  recommendedRank: Rank;
}

interface StageMaster {
  id: string; worldId: string; name: string;
  type: 'stage' | 'dungeon';
  battles: EnemyParty[];      // stageは1件、dungeonは3〜5件＋ボス
  extraRuleIds?: string[];    // 高難度の追加ルール
  rewards: RewardTable;       // ゴールド・経験値・素材・装備・ドロップ率
  firstClearRewards: Reward[];
  bossLine?: string;
}
```

その他のマスター：ガチャバナー（期間・ピックアップ・排出表）、任務、イベント（期間・世界ID・交換所の表と上限）、拠点施設（レベルごとのコストと効果）、ランクごとの総量・必要経験値・昇格コスト・スキルポイント表、PvPシーズン設定（週替わりルールの順番）、NPC防衛編成。

## 17. 実装フェーズ

Codexには1フェーズずつ依頼し、動作確認してから次へ進む。

1. **戦闘エンジン**：`packages/engine` に3章の仕様を実装。シード付き乱数、Vitestによるテスト。サンプルのキャラ・スキルデータで戦闘を実行し、スナップショットを表示する簡易テストページ（仮アイコン使用）
2. **マスターデータ基盤**：型定義、JSONの読み込み、データの整合性チェック（存在しないIDの参照などを検出するスクリプト）
3. **サーバー基盤**：Workers + Hono + D1、アカウント作成・引き継ぎ、`/api/me`
4. **育成**：ステータス計算（4.3）、レベル・昇格・覚醒・スキル構成・装備・分解・控え枠
5. **冒険**：世界・ステージ・連戦ダンジョン、報酬、仲間化、間隔制限、まとめて周回、戦闘結果画面
